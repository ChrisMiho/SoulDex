# Colour themes implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** four colour themes, picked in the options, applied live to every window surface and the rank emblems.

**Architecture:** a pure `Themes` module holds the palettes; `UIFormat.COLORS` is refilled in place from the active palette; the `UIList` painting helpers accept slot names and remember what they painted so a theme change repaints it all.

**Tech stack:** Lua 5.1 (WoW: Forever, Interface 16001), busted, luacheck; headless Chrome + Pillow for the emblems.

**Spec:** `docs/superpowers/specs/2026-11-18-themes-design.md` (palette table and slot names are there).

## Global constraints

- Pure modules call no WoW API; tested through `LoadAddonFile`.
- Every new WoW API in `.luacheckrc` `read_globals`; no new globals.
- New files go in `SoulDex.toc` above `src\Init.lua` and get `git add`ed.
- Soul Shard values are exactly today's; rarity and class colours never change.

## Review focus

- A saved theme id that no longer exists (or junk: a number, a table) loads as Soul Shard.
- Switching theme with the window closed, then opening it: everything in the new theme.
- Switching while the trophy card is open, or on the Friends tab: no stray old colours.
- A popup already on screen when the theme changes keeps working (its accent updates on the next show).
- Mastery star text built before the change (cached row text) is rebuilt on refresh.
