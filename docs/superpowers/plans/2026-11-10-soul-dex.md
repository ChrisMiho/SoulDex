# Soul-Dex Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A WoW: Forever warlock addon that records the source of every Soul Shard you collect (mob, player or raid mob), shows the collections in a small tabbed window, and adds points, milestones, a new-catch popup, shard tooltips and friend comparison.

**Architecture:** Pure Lua modules (no WoW API) own every decision: matching a shard to a death, the bag slot map, the dex data model, points, milestones, flavour text, the rows each tab shows, and the friend protocol. They are tested with busted. Thin glue files own events, frames, tooltips, chat and addon messages. Same layout and tooling as `C:\Coding\DeathRollForever`.

**Tech Stack:** Lua 5.1, WoW: Forever client (`## Interface: 16001`), busted, luacheck, BigWigs packager, AceComm-3.0 (with LibStub, CallbackHandler-1.0) via `.pkgmeta`.

**Spec:** `docs/superpowers/specs/2026-11-10-soul-dex-design.md` (read it before any task; section numbers below refer to it).

## Global Constraints

- Code name `SoulDex`: `SoulDex.toc`, `package-as: SoulDex`, `## Title: Soul-Dex`, `## SavedVariablesPerCharacter: SoulDexDB`. Slash command `/souldex` only.
- `## Interface: 16001`, `## Author: ChrisMiho`, `## Version: @project-version@`, MIT licence (copy `C:\Coding\DeathRollForever\LICENSE`).
- Every file starts with `local addonName, ns = ...` (or `local _, ns = ...`); share through `ns`, never new globals.
- Pure modules call no WoW API and are tested through `LoadAddonFile`. Game code lives only in the glue files named in each task.
- Every WoW API used goes in `read_globals` in `.luacheckrc`; every global created goes in `globals`.
- Libraries only through `.pkgmeta` externals pinned to `Release-r1403` and `embeds.xml`; never commit `Libs/`.
- Tabs for indentation; `.editorconfig` copied from DeathRollForever.
- Personal output goes to `DEFAULT_CHAT_FRAME` only; the only chat-channel output is guild announcements (spec 6.4).
- Palette (from the approved mockups): window bg `#14101c`, border `#6b4fa0`, title text `#c9a8ff`, divider `#3d2d5c`, selected row `#3a2a55`, muted text `#9a8fb0`, header text `#8a72b8`, pane bg `#0d0a14`, Back button bg `#251b36` / border `#5a4486` / text `#c9a8ff` / hover bg `#3d2d5c`, unknown `#4d4360`, points green `#7dff6a`, flavour `#ffd100`.
- Never record a wrong name in the dex. A shard with no matching death records nothing.
- `luacheck .` and `busted` pass at the end of every task.

## Review Focus

1. **Bags full, no shard arrives.** A drained mob dies but no shard appears: nothing is recorded, and the waiting candidate expires so a later shard isn't wrongly linked to it. (Task 6 test `expires candidates after the window`.)
2. **A shard is used in the same bag scan as a new one arrives.** The new catch must still be recorded, not mistaken for a moved shard. (Task 7 test `pending catch wins over a move`.)
3. **Garbage or newer-version addon messages.** Another player's message from a future version, or a truncated one, is ignored without a Lua error. (Task 12 tests `rejects unknown versions` and `rejects truncated payloads`.)
4. **The same mob name seen at different levels or ranks** (e.g. a mob at level 10 and 12): one entry, with the level range widened, never two. (Task 4 test `widens the level range`.)
5. **Friend names typed with odd capitals or a realm suffix** ("stabbyface", "Stabbyface-Forever") match the same person. (Task 12 test `normalises names`.)

### Task 7: Bag slot map

**Files:**
- Create: `src/Shards.lua`
- Test: `spec/Shards_spec.lua`

**Interfaces:**
- Produces: `ns.Shards.update(map, slots, pending) -> newMap, gained` where `map` is `{ ["bag:slot"] = soul }` (saved as `db.shardSlots`), `slots` is the current list of `"bag:slot"` strings holding a Soul Shard, `pending` is a bool (matcher has a candidate), and `gained` is the list of slot keys that hold **new** shards (the caller fills them with souls). `soul = { name, color, zone, time }`.

Rules: unchanged slots keep their soul. Let A = new slots, R = vanished slots. `newCount = max(#A - #R, 0)`, but if `pending` and `#A > 0` and `newCount == 0`, `newCount = 1` (Review Focus 2). The first `newCount` of A (sorted) are `gained`; the rest of A are paired with R in sorted order and inherit their souls (moves; names may swap, spec 6.3); leftover R are dropped.
